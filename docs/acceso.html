1. Requisitos de Conexión

  1. Tailscale conectado en tu equipo: Ejecuta tailscale status y verifica que el nodo seclab-sbf-prod (100.111.178.40) esté visible.
  2. Clave privada SSH: Debe encontrarse en .secrets/ssh/seclab_ed25519 con permisos estrictos 600.
  3. Contraseña Web ttyd: Consulta tu clave en el archivo local con: 
    grep TTYD_PASSWORD .env

2. Comandos Make de Acceso Rápido (Recomendado)

Ya configuramos CLOUD_HOST=100.111.178.40 en tu archivo local .env, por lo que no necesitas ingresar la IP ni especificar la ruta de las llaves manualmente:

A. Entrar al Laboratorio de Pentesting (Contenedor Tester)

Abre la shell interactiva como usuario tester (sesión tmux, zsh, plugins, herramientas de auditoría en puerto 2222):

make lab-ssh-cloud

B. Entrar a la Administración del VPS (Host Ubuntu)

Abre la sesión de administración como usuario ubuntu (docker, systemd, firewall, logs en puerto 22):

make host-ssh-cloud

3. Comandos SSH Directos Equivalentes

A. Host VPS (Puerto 22, usuario ubuntu)

ssh -i .secrets/ssh/seclab_ed25519 ubuntu@100.111.178.40

Comandos útiles en el host:

cd ~/seclab-sbf
sudo systemctl status seclab-nftables fail2ban --no-pager

sudo nft list table inet seclab_host

B. Contenedor Lab (Puerto 2222, usuario tester)

6. Seguridad y Buenas Prácticas

Zero Ingress Enforced: La IP pública 158.23.145.139 solo tiene función de salida a internet (egress para descargar paquetes/herramientas sin costo de NAT Gateway). Cualquier intento de conexión entrante a esa IP es descartado de inmediato por el NSG de Azure y por la cadena input de nftables (política DROP). Todo el tráfico administrativo transita únicamente por la interfaz tailscale0.

7. Solución de Problemas

SíntomaDiagnóstico y Solución
Permission denied (publickey) Asegúrate de pasar la llave .secrets/ssh/seclab_ed25519 y verifica que sus permisos sean chmod 600.
Timeout al conectar a 100.111.178.40 Verifica que la app de Tailscale en tu Mac esté activa (verde) y ejecuta tailscale ping 100.111.178.40.
Login incorrecto en Web (7681) Verifica tu variable TTYD_PASSWORD en el .env tanto local como en el remoto (~/seclab-sbf/.env).
Host bloquea conexiones SSH temporalmente Fail2ban protege el puerto SSH. Si hubo 5 intentos fallidos, espera 10 minutos o ejecuta desde consola de Azure: sudo fail2ban-client set sshd unbanip <tu-ip-tailscale>.
