Acceso al laboratorio ●

seclab-sbf-prod · tailnet únicamente · sin puertos públicos · VM sin IP pública

0. Requisitos (una vez)

  1. Tailscale conectado en tu Mac: tailscale status debe mostrar seclab-sbf-prod con IP 100.113.178.15.
  2. Llaves del proyecto en /Users/castr/tmp/t01/.secrets/ssh/: seclab_ed25519 (lab) y seclab_console_rsa (consola OCI).
  3. Contraseña web: la obtienes con grep TTYD_PASSWORD /Users/castr/tmp/t01/.env (cámbiala si aún es la de defecto).

1. VPS por SSH (host Ubuntu)

Sesión de administración del host

ssh -i /Users/castr/tmp/t01/.secrets/ssh/seclab_ed25519 ubuntu@100.113.178.15

Desde ahí, el repo vive en ~/seclab-sbf. Comandos útiles:

cd ~/seclab-sbf
export WORKSPACE_DIR=/opt/seclab-sbf/workspace LAB_ENV_FILE=.env
sudo systemctl status seclab-nftables seclab-ttyd-tailnet seclab-ssh-tailnet --no-pager
docker compose -f compose.yaml -f compose.local.yaml -f compose.vpn-inside.yaml ps

2. Contenedor por SSH (usuario tester)

En tu Mac (un comando)

make lab-ssh

Levanta el lab si hace falta, publica 127.0.0.1:2222 vía override temporal (sin tocar compose.yaml) y entra como tester con banner + tmux.

Construye la imagen en tu Mac si falta o si el código ha cambiado: la imagen lleva una etiqueta con un hash de sus ficheros de build y ensure-image la compara. Si no coinciden, reconstruye. Si nada cambió, no toca nada.

Si el puerto está ocupado: make lab-ssh LAB_SSH_PORT=2223. Para la imagen full: make lab-ssh-full. La imagen base no admite sesión (no trae sshd ni usuario tester); se valida con make base-check.

Dudas de qué imagen o perfil van a entrar: make profile-info.

En el contenedor del host cloud (un comando)

make lab-ssh-cloud TF_HOST=100.113.178.15

Entra directo por el tailnet, sin túnel. El puente lo publica el servicio systemd seclab-ssh-tailnet en la IP Tailscale del host, así que no hace falta ningún override de puertos. Acepta TF_HOST o CLOUD_HOST (queda en el .env).

Esto entra tal cual está el contenedor. Para la imagen full:

make lab-ssh-cloud-full

Que recrea el lab en el host antes de entrar, compilando allí la imagen si hace falta o si el código del host cambió.

El repo del host se actualiza por git archive + scp, no es un clon (el repo es privado y el host no tiene credenciales de GitHub). Si has cambiado código en tu Mac y quieres que el host lo use, resincroniza antes; si no, el host se queda con lo suyo.

Imágenes: dónde están y cuál usar digest

ImagenDónde se construyeNotas
base, lightSe publican en GHCR por digest en cada releaseEl host no compila nada: hace docker pull. Son multi-arch (amd64 y arm64).
fullEn el host donde va a correrNo se publica. Se compila allí de forma nativa porque la pata arm64 emulada con QEMU tarda más de 2 h. Sus CVEs se comprueban con make scan-image.
Ojo con los digest. Una referencia ghcr.io/...@sha256:... no lleva el nombre del perfil, así que no hay forma de deducir si la imagen es full o light. Antes de adivinar light y arrancar el laboratorio sin Metasploit sin avisar, check-profile lo corta. Pásalo explícito: 
make lab-ssh-cloud-image LAB_IMAGE=ghcr.io/hackadvisermx/seclab-sbf@sha256:<digest> LAB_PROFILE=full
Un tag normal (seclab-sbf:full o :light) sí se deduce solo.

Directo por el tailnet, sin túnel (puerto 2222, solo llaves)

ssh -i /Users/castr/tmp/t01/.secrets/ssh/seclab_ed25519 -p 2222 tester@100.113.178.15

Entrarás al shell del laboratorio (banner SECLAB-SBF). Alternativa desde el host con docker compose exec (no usa red).

3. Contenedor por web (ttyd)

Terminal en el navegador

Abre http://100.113.178.15:7681 e inicia sesión con usuario tester y tu TTYD_PASSWORD.

La sesión es tmux persistente: cerrar el navegador no la mata. El túnel ssh -L ya no hace falta (quedó como alternativa).

4. Si algo falla

SíntomaCausa probable / solución
Permission denied (publickey)Usa -i con la llave correcta (seclab_ed25519, no la de consola).
Timeout al puerto 7681/2222Tailscale caído en Mac o host; revisa tailscale status en ambos. Revisa los servicios systemd del host.
ttyd pide login en bucle / 401Contraseña incorrecta: verifica TTYD_PASSWORD de tu .env local.
exec request failed / PTY, warptmp, /.zshenv read-only, o SSH sin tmux ni bannerEstás en Warp: su integración remota rompe el login (fija ZDOTDIR=/). Atajo en sesión: ZDOTDIR=/home/tester exec /usr/bin/zsh -il. Permanente: usa /usr/bin/ssh, Terminal.app, o desactiva por completo la integración SSH/shell de Warp.
no se deduce el perfil de un digest remotoHas pasado una imagen por digest sin decir si es full o light. Añade LAB_PROFILE=full (o light) al comando.
El contenedor arranca pero sin Metasploit ni NetExecSe quedó en perfil light. Comprueba con make profile-info y recrea con make lab-ssh-cloud-full.
La imagen del host parece viejaEl repo del host lleva otro código. Resincroniza el repo al host; ensure-image lo detecta por la etiqueta de insumos y reconstruye solo.
msfconsole: ruby not foundEl PATH de /opt/ruby/bin lo añaden sshd_config y el zshrc, no un su a pelo. Entra por SSH o por el terminal web, no con docker exec su tester -c.
Todo el tailnet fallaÚltimo recurso: console connection de OCI (llave seclab_console_rsa, login ubuntu + contraseña de consola). Pregunta por el comando vigente.
Pendientes de seguridad (tu lado admin): ACL del tailnet en deny-by-default, MFA y device approval (admin.tailscale.com), y eliminar la máquina vieja seclab-cloud-20260924154553. Además: cambia TTYD_PASSWORD si sigue siendo el valor de defecto y reinicia el contenedor lab para aplicarlo.
