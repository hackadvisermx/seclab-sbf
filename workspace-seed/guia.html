🗺️ Metodología Paso a Paso: De Inicio a Fin

Sigue este flujo secuencial estandarizado para asegurar cobertura del 100%, rigor Evidence-First y cero omisiones:

1
Inicialización y Definición de Alcance (Scope Guard)
Crea la estructura del engagement. SecLab inicializa las carpetas evidence/, recon/, notes/, scope/ y genera el archivo scope/target.yaml con reglas estrictas de dominios, CIDRs y exclusiones. 
pt-eng new mi-objetivo target.com
cd /workspace/engagements/mi-objetivo
# Valida que un objetivo o URL pertenezca al alcance permitido:
pt-eng scope https://target.com/api
🔒 Scope Guard Activo: Cualquier herramienta del laboratorio consulta target.yaml. Intentar escanear destinos fuera de alcance bloqueará la ejecución para evitar ataques no autorizados.
2
Reconocimiento Automatizado & Fuzzing de Parámetros
Ejecuta la batería de enumeración pasiva y activa: subdominios (assetfinder, findomain), sondeo HTTP (httprobe), scraping de endpoints (gau) y parámetros ocultos con x8. 
# Reconocimiento continuo con scope guard:
pt-recon mi-objetivo

# Fuzzing determinista de parámetros ocultos con x8:
pt-fuzz-params https://target.com/api/v1/user
3
El Asesor Táctico: ¿Qué hago ahora? (pt-next)
En cualquier momento de la auditoría, pt-next analiza los artefactos existentes, notas y hallazgos registrados para decirte exactamente qué paso metodológico sigue. 
# Recomienda el próximo paso táctico con comandos listos:
pt-next

# Muestra el mapa de ruta completo de las 8 disciplinas:
pt-next --all

# Genera un System Prompt enriquecido con el estado real para tu LLM / Agente:
pt-next --prompt
4
Auditoría Específica por Disciplinas (Agent Security Skills)
Aplica playbooks profesionales categorizados. Si pruebas SSRF o inyecciones fuera de banda (OOB), usa el receptor local pt-callback. 
# Abre el selector interactivo fzf de playbooks de seguridad:
pt-skills

# En otra pestaña/panel tmux, inicia el receptor de interacciones OOB para SSRF:
pt-callback listen 9001

# Lanza payload con UUID único para rastrear la interacción:
pt-callback trigger http://127.0.0.1:9001
5
Documentación Evidence-First & Compuertas de Calidad Bug Bounty
Todo hallazgo debe documentarse con evidencia reproducible, requests/responses HTTP sin alterar y scoring CVSS v3.1. SecLab incorpora compuertas estrictas para descartar falsos positivos y acotar pruebas:
1. Credential Gate Paso 2b / Paso 6
Ante tokens o API keys expuestos, ejecutar llamada autenticada y contrastar obligatoriamente con un Control Negativo (petición sin token o con token alterado). Si ambas devuelven igual respuesta, se descarta como falso positivo.
2. Enrutamiento de Acceso target.yaml
RICH: 2+ cuentas activas → IDOR cruzado bidireccional (A accede a B y B a A).
PARTIAL: 1 cuenta → BFLA y mutación de estado propio.
UNAUTH: Sin cuentas → Superficie pre-auth y fugas en SPA.
3. Bounded Testing (BDT) Regla Operativa
Límite estricto de 1-3 peticiones de prueba por vector. Nunca manipular datos ni cuentas de terceros. Revertir inmediatamente cualquier mutación generada.
4. Ciclo Evidence-First Estados
PROVEN: Verificado con PoC reproducible e impacto demostrable.
CANDIDATE: Vector preliminar sin prueba concluyente.
DISPROVED: Descartado tras test de control negativo.
MITIGATED: Verificado como subsanado. 
# Crea la plantilla estructurada del hallazgo:
pt-finding new idor-panel-facturacion

# Edita evidence/idor-panel-facturacion.md y valida la rigurosidad técnica:
pt-finding lint
6
Evaluación de Cobertura y Checklist Metodológico
Comprueba el porcentaje de avance en las 8 disciplinas metodológicas. Para poder cerrar el engagement se exige un mínimo de 50% de cobertura. 
# Evalúa la cobertura en vivo:
pt-checklist

# Genera tabla en formato Markdown para adjuntar al informe:
pt-checklist --markdown
7
Compilación de Reportes, Cierre y Empaquetado Seguro
Compila el reporte final, pasa la compuerta de calidad pre-cierre y genera el tarball sanitizado con SHA-256 en dist/. 
# 1. Compila el reporte técnico y ejecutivo en Markdown:
pt-report compile

# 2. Verifica la compuerta de calidad antes de cerrar:
pt-eng close

# 3. Sanitiza tokens/claves y empaqueta reproduciblemente con SHA-256:
pt-eng pack

🎯 Matriz de las 8 Disciplinas Metodológicas

SecLab estructura las pruebas en 8 áreas. Haz clic en los comandos para copiarlos:

1. Recon & Profiling Fase 1
Descubrimiento de subdominios, tecnologías, certificados y superficie expuesta.
pt-recon [target]
2. Param Discovery Fase 2
Fuzzing de parámetros ocultos, scraping de URLs pasivas y paths en endpoints.
pt-fuzz-params [url]
3. Auth & Authorization Fase 3
Matriz de roles, IDORs cruzados, bypass de autenticación, JWT y fallos de sesión.
pt-skills auth-matrix-audit
4. Business Logic Fase 4
Condiciones de carrera, alteración de precios, flujos de carrito y estado.
pt-skills business-logic-audit
5. Inyecciones & SSRF Fase 5
SQLi, SSRF, SSTI, Command Injection con validación fuera de banda (OOB).
pt-callback listen 9001
6. Client-Side SPA Fase 6
DOM XSS, postMessage inseguros, fugas de secretos en bundles JS y CSP bypass.
pt-skills client-side-spa-audit
7. API Security Fase 7
Mass assignment, rate limiting, GraphQL introspection y OpenAPI testing.
pt-skills api-security-audit
8. Triage & Reporting Fase 8
Descarte de falsos positivos, severidad CVSS v3.1 y compilación del informe.
pt-report compile
